# MAX ↔ Telegram Bridge

Двусторонний мост между мессенджером **MAX** (web.max.ru / oneme.ru) и ботом **Telegram**.

- Входящие сообщения MAX → в тему (topic) супергруппы Telegram, **по одной теме на каждый MAX‑чат**.
- Ответ в теме Telegram → уходит обратно в соответствующий MAX‑чат.
- Полное управление через кнопки Telegram‑бота (только для админов привязанной группы).

> ⚠️ Использует неофициальный (reverse‑engineered) API MAX. Это нарушает условия MAX и создаёт риск блокировки аккаунта. Только для личного/образовательного использования. Никаких гарантий.

## Что пересылается из MAX в Telegram

| Содержимое MAX | Как выглядит в Telegram |
|---|---|
| Текст | Обычное текстовое сообщение в теме чата, с именем отправителя в заголовке |
| Фото | Загружается и пересылается как фото (конвертация WebP → JPEG) |
| Файл (документ) | Загружается и пересылается как документ |
| Видео | Ссылка на файл (Telegram сам показывает превью по ссылке — видео с MAX отдаются по подписанным CDN‑ссылкам, которые неудобно перекачивать через бота) |
| Пересланное (forward) сообщение | Помечается стрелкой `↪` перед именем автора |
| Голосовое сообщение | Плейсхолдер «🎤 Голосовое сообщение (m:ss)» — у MAX нет публичной ссылки на файл для таких вложений (см. «Известные ограничения» ниже) |
| Голосование (опрос) | Плейсхолдер «📊 Голосование» (+ текст вопроса, если сервер его передаёт) — схема JSON для опросов MAX нигде не задокументирована, поэтому вопрос извлекается «на лучших основаниях» |
| Реакция на сообщение (👍/❤️/…) | Отдельной строкой «🔔 Реакция: 👍 x2» в той же теме |
| Любое нераспознанное/недокачиваемое вложение | Плейсхолдер «📎 Неподдерживаемое вложение (ТИП)» вместо того, чтобы сообщение просто пропало |
| Своё же сообщение, отправленное из приложения MAX (не через бота) | Дублируется в тему с префиксом `➡️` — так видно, что где‑то ответили напрямую из MAX |

Направление Telegram → MAX (ответ в теме) поддерживает текст, фото и произвольные документы.

При создании новой темы (первое сообщение из нового MAX‑чата) бридж дополнительно подтягивает аватар чата и бэкфиллит последние сообщения (см. `history_count` в конфиге).

## Как это работает

- **MAX**: постоянное WebSocket‑соединение `wss://ws-api.oneme.ru/websocket` (JSON, ver 11). TLS‑хендшейк маскируется под Firefox (uTLS), т.к. edge/WAF MAX обслуживает только «браузерные» подключения; ALPN жёстко зафиксирован на `http/1.1` (WebSocket‑апгрейд не работает поверх HTTP/2 — без этой фиксации edge иногда выбирал h2 и соединение падало с `malformed HTTP response`). Авторизация — токен доступа (см. ниже). Соединение **всегда прямое**, никогда не идёт через прокси Telegram.
- **Входящие сообщения** приходят пушем на опкоде `128`; **реакции** — на опкоде `155` (плоский payload) либо `156` (payload вложен в `reactionInfo`, по документации) — оба варианта обрабатываются. Остальные пуш‑опкоды (тайпинг, presence, синхронизация конфигов/эмодзи и т.п.) — служебные и игнорируются.
- **Telegram**: обычный Bot API (long‑polling `getUpdates`). Опционально весь трафик Telegram (и только он) идёт через SOCKS5‑прокси.
- **Токен MAX** берётся одним из двух способов:
  - из открытого браузера, залогиненного в web.max.ru, через Chrome DevTools Protocol (сервис сам запускает Edge/Chrome в режиме отладки);
  - через SMS‑авторизацию прямо из бота (без браузера).
- **Управление**: в личке боту (только админам группы) — кнопки: статус, перезапуск, SMS‑авторизация, логи, диагностика MAX, сырой debug‑лог, тестовое сообщение, ручной ввод токена/опкода.

## Требования

- Windows.
- Go 1.25+ (только для локальной сборки — GitHub Actions собирает сам, см. ниже).
- Телеграм‑бот (токен от [@BotFather](https://t.me/BotFather)).
- Супергруппа Telegram с включёнными **темами (topics)**; бот добавлен в неё **администратором**.
- Для захвата токена из браузера — установленный Edge или Chrome и один раз выполненный вход в web.max.ru (профиль запоминается). Либо SMS‑авторизация.

## Сборка

Локально:

```
go build -o dist/maxtg.exe .
```

Через GitHub Actions (без локального Go):

- Любой пуш в `main` гоняет `ci.yml` — `go vet` + `go build` + `go test` на Ubuntu, просто проверка, что всё компилируется.
- Пуш тега вида `vX.Y.Z` (или запуск `release.yml` вручную из вкладки Actions → workflow_dispatch) собирает `maxtg.exe` на `windows-latest`, упаковывает `MaxTgBridge-windows-amd64.zip` (exe + `install.bat`/`uninstall.bat`/`config.example.json`/README) и публикует их как GitHub Release с автосгенерированными release notes.

```
git tag v1.1.1
git push origin v1.1.1
```

## Установка и запуск

1. Запусти `maxtg.exe` без аргументов — откроется консоль настройки (при незаполненном конфиге сразу стартует мастер первого запуска).
2. Укажи телефон MAX, токен бота, при необходимости SOCKS5‑прокси для Telegram и CDP‑адрес браузера.
3. Получи токен MAX: пункт **2** «Pull MAX token from browser» (откроется Edge — войди в web.max.ru один раз) **или** пункт **1** — SMS‑авторизация прямо в консоли.
4. Добавь бота в группу администратором и отправь в группе любое сообщение — ID группы определится автоматически (или пункт **5** «Detect Telegram group id»).
5. Пункт **9** «Install / update autostart» — бридж будет стартовать при входе в систему (обычное приложение в сессии пользователя, без службы и прав администратора).

При заполненном конфиге консоль теперь **сама поднимает мост в фоне сразу при запуске** — вручную жать «8. START the bridge now» больше не нужно (актуально начиная с v1.1.0). Пункт 8 остаётся в меню на случай, если мост пришлось остановить и перезапустить вручную.

Полное меню консоли:

| № | Действие |
|---|---|
| 1 | SMS‑авторизация (получить токен MAX) |
| 2 | Забрать токен MAX из открытого браузера (CDP) |
| 3 | Вставить готовый токен MAX вручную |
| 4 | Проверить связь с Telegram (`getMe`, с учётом прокси) |
| 5 | Определить ID группы Telegram |
| 6 | Изменить настройки (повторно открыть мастер) |
| 7 | Показать статус |
| 8 | Запустить мост в фоне вручную |
| 9 | Установить/обновить автозапуск при входе в систему |
| 10 | Показать последние строки лога |
| 11 | Отправить тестовое сообщение в Telegram |
| 0 | Выход |

Команды из командной строки: `maxtg.exe console` (то же меню), `maxtg.exe run` (сразу запустить мост, используется автозапуском), `maxtg.exe install` / `uninstall` (авто­запуск при логоне без прав администратора).

## Управление через бота

В личке боту (только для админов привязанной группы) — графическое меню с кнопками, которые под капотом шлют команды:

| Команда | Что делает |
|---|---|
| `/status` | Статус подключения MAX (подключён/отключён, ID, последняя ошибка), ID группы Telegram |
| `/restart` | Перезапустить бридж (переисполняет процесс на месте) |
| `/auth [phone]` | Запустить SMS‑авторизацию MAX; код присылается сообщением из 4–8 цифр |
| `/code 123456` | Ввести SMS‑код во время активной авторизации |
| `/captcha <token>` | Ввести токен капчи, если MAX её потребовал |
| `/settoken <token>` | Вручную задать токен MAX (например, добытый из DevTools браузера) |
| `/pulltoken` | Забрать токен MAX из открытого браузера через CDP |
| `/setopcode <N>` | Явно задать опкод входящих сообщений (обычно не нужно, дефолт — 128) |
| `/testmsg` | Отправить тестовое служебное сообщение в General |
| `/maxdiag` | Прогнать диагностику соединения с MAX (DNS/TCP/TLS/WS‑апгрейд/INIT) |
| `/log [N]` | Последние N строк лога (по умолчанию 20) |
| `/debuglog` | Последние сырые фреймы (opcode + payload), пришедшие от MAX — самый полезный инструмент при разборе новых типов вложений/пушей |

## Конфигурация (`config.json`)

Скопируй `config.example.json` в `config.json` и заполни. На Windows рабочий конфиг лежит в `%ProgramData%\MaxTgBridge\config.json`.

| Поле | Описание |
|------|----------|
| `max_ws_url` | WebSocket MAX (по умолчанию `wss://ws-api.oneme.ru/websocket`) |
| `phone` | Телефон MAX в формате `+7XXXXXXXXXX` (для SMS‑авторизации) |
| `telegram_bot_token` | Токен бота от @BotFather |
| `telegram_group_id` | ID супергруппы (`0` = определить автоматически) |
| `telegram_proxy` | SOCKS5‑прокси **только для Telegram** (пусто = напрямую), напр. `socks5://host:1080` или `socks5://user:pass@host:1080`. MAX всегда идёт напрямую. |
| `browser_cdp_url` | CDP‑endpoint браузера для захвата токена (по умолчанию `http://127.0.0.1:9222`) |
| `browser_match_url` | URL‑подстрока страницы MAX (по умолчанию `web.max.ru`) |
| `state_path` | Файл состояния (токен, deviceId, карта чат↔тема, offset) |
| `incoming_opcode` | Опкод входящих сообщений (`0` = дефолт `128`) |
| `history_count` | Сколько последних сообщений подтягивать в новую тему при её создании (по умолчанию 20, максимум 200, `0` — не бэкфиллить вовсе) |

## Известные ограничения

- **Голосовые сообщения и часть файлов не пересылаются как файл**, только уведомлением. MAX в пуше отдаёт для них лишь внутренний `fileId`/`token` без прямой публичной ссылки — открытого способа скачать сами байты без дальнейшего реверс‑инжиниринга протокола не найдено. Фото и большинство документов при этом пересылаются полностью, т.к. у них есть прямой URL.
- **Текст голосования (вопрос/варианты)** извлекается по неподтверждённым предположениям о названиях полей — реальная схема JSON для опросов MAX нигде не задокументирована. Если вопрос не показывается, пришли `/debuglog` сразу после создания опроса — так можно уточнить парсинг под реальный формат.
- Видео пересылается ссылкой, а не файлом (подписанные CDN‑ссылки MAX неудобны для перекачки через бота, но Telegram обычно показывает превью по ссылке сам).
- Прокси применяется только к Telegram; для MAX его нет и не будет (не совместимо с TLS‑фингерпринтингом под Firefox).

## Устранение неполадок

- **`dial: malformed HTTP response "\x00\x00\x1e\x04..."`** — это сырые байты HTTP/2‑фрейма SETTINGS. Означает, что TLS согласовал ALPN `h2` вместо `http/1.1` на связке с MAX‑WebSocket. Исправлено с v1.1.0 жёсткой фиксацией ALPN; если видите это на более старой сборке — обновитесь.
- **MAX: Отключен / нет токена** — забери токен заново через браузер (пункт 2 в консоли / `/pulltoken` в боте) или через SMS (пункт 1 / `/auth`).
- **Сообщения из MAX не приходят вовсе** — проверь `/status` и `/debuglog`: если опкод входящих сообщений вдруг сменился на стороне MAX, `/debuglog` покажет реальный номер опкода в сыром виде.
- **Reply/getUpdates не отвечает** — проверь `/log`, обычно означает проблему с прокси или неверный токен бота.
